# nvda-rig

Drives NVDA and Firefox to capture screen-reader transcripts, so an
accessibility question can be answered with evidence rather than recollection.

Runs inside a Windows 11 **ARM64** guest under UTM on a Mac. Targets are either
local fixtures or `http(s)` URLs — the URL form is how a Vite dev server on the
host gets driven from inside the guest.

## Four things that are not obvious

These cost real time to discover. They are why this repo exists.

1. **A run must be started by a scheduled task, not over SSH.** An SSH session
   has no interactive desktop, so NVDA has no foreground window to describe.
   Tasks `nvda-smoke`, `nvda-probe` and `nvda-run` are registered with `/it` so
   they land in the logged-in console session.

2. **Do not call `windowsActivate` unconditionally after launching Firefox.**
   Its VBScript ends in `SetForegroundWindow`, which Windows refuses from a
   non-elevated process while an elevated window holds the foreground — and the
   guest desktop runs an elevated VS Code and PowerShell. About half the time it
   leaves focus on Firefox's hidden menu bar: NVDA reports `menu, off screen`
   while the page reports `document.activeElement === body`. The title still
   names Firefox, so a title guard passes and the transcript fills with
   plausible silences. A freshly launched `-new-window` Firefox is already
   foreground with its content focused; activate only if the guard asks.

3. **`F6` is the only recovery key.** It cycles Firefox's focus back into the
   content area. `Escape` and a second `windowsActivate` were both measured and
   neither recovers. Every other key lands on the address bar, where a letter is
   typed as text rather than navigating.

4. **Browse-vs-focus mode cannot be queried, only asserted.** In focus mode
   every quick-navigation command is passed through to the page and answers with
   silence. `reportCurrentFocus` does not say which mode it is in (it appends an
   object-replacement character in focus mode, but that was measured to be
   unreliable). So the mode is proved behaviourally: quick-navigate, and toggle
   if the attempt is silent.

## Layout

```
lib/          the rig core — everything above, encoded once
  session.cjs   NVDA lifecycle, openTarget(): launch, focus guard, mode guard
  guard.cjs     ensureReadyToNavigate() — points 2, 3 and 4
  firefox.cjs   hermetic profile, launch
  speech.cjs    SpeechLog — reads NVDA's cumulative log without dropping phrases
  target.cjs    fixture-or-URL resolution, provenance, settle timings, queue parsing
  steps.cjs     step specs ("perform:x" / "press:y") and the step loop
  stamp.cjs     the environment block at the head of every transcript
  system.cjs    delay, taskkill, powershell, git blob hash, window list

runner.cjs    reads queue.txt, writes runs/<runId>/<slug>.txt + DONE
probe.cjs     reads probe.json + probe-fixture.txt, writes probe-out.txt
smoke.cjs     one target, four steps: does the rig work on this machine right now?
fixtures/     generated by build-fixtures.mjs; committed so their hashes mean something
test/         the parts that need no desktop
```

## Running

```
npm test                          # pure logic, runs anywhere, no NVDA needed
Start-ScheduledTask nvda-smoke    # live check that the rig works at all
Start-ScheduledTask nvda-probe    # iterate on a key sequence
Start-ScheduledTask nvda-run      # the queue
```

`npm run smoke` and friends exist too, but only work if the shell you are in is
already on the interactive desktop. The scheduled task is the reliable path.

Copy `queue.example.txt` to `queue.txt` and `probe.example.json` to `probe.json`
to get started; both are gitignored, being scratch.

## Reading a transcript

Every transcript starts with the exact Windows, Firefox, NVDA, guidepup and Node
builds that produced it, plus the git blob hash of the fixture's bytes. Without
that block a diff between two runs cannot be attributed — NVDA's phrasing and
Firefox's accessibility tree both change between releases. A real example: a
toolbar announcement changed wording between Firefox 155.0.1 and 156.0, and the
stamp is the only reason that was identifiable as environment drift rather than
a regression in the page under test.

`(silence)` is written out explicitly, because a blank line in a transcript is
indistinguishable from a formatting accident.

## Where this is going

- **Phase 2** — move `sequence()` out of `runner.cjs` into scenario files a
  consuming repo owns, so it can test its own components without forking.
- **Phase 3** — assertions and committed snapshots, so a run can fail a build.
- **Phase 4** — an HTTP daemon in the guest so the host can await a run, instead
  of writing a queue file and polling for `DONE`.
- **Phase 5** — provisioning, so a fresh UTM image is one command from working.
- **Phase 6** — split into a guest package and a host-side dev dependency.
