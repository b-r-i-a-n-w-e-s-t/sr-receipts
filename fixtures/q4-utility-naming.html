Q4: does visually hidden text name a utility column where aria-label does not?

Fixture: q4-utility-naming.html (generated by build-fixtures.mjs; edit the generator, not this file).

Answers Q4 of .scratch/columnlist-table-roles/assets/09-verification-protocol.md §8. The M1 pass found that aria-label on a columnhead div is never spoken by NVDA, in the header row or in the header-on-cell-entry announcement, leaving Select, Expand, Columns and shape G’s mirrored Details silent.

Three tables, seven columns each, identical in every byte except how the four text-less utility headers are named. Variant A is the control: it reproduces the known failure, so if A announces the names then something about this run differs from M1 and no conclusion can be drawn from B or C. Last Survey, Style and Actions are named by rendered text in all three and should announce everywhere.

Listen for: in each table, two channels for the same four columns. Header row: walk it with Ctrl+Alt+Right and hear whether column 2 says "Expand" or a bare "column 2". Cell entry: walk a data row and hear whether the header prefixes the cell. Then three specifics: whether the select-all header leaks the checkbox’s own "select all" label into a doubled name (the concern that made 06 choose aria-label in the first place), whether variant C appends "off screen" to every utility header it names, and whether the zero-width Details column behaves like the others.

Variant A, aria-label

Utility columns named by aria-label="..." on the columnhead div — what 06 decision 2 specified and what ships in the spec today. Known to be silent on NVDA; present here as the control.
